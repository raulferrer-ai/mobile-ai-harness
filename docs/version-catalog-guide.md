# Version Catalog Guide - mobile-ai-harness

This guide documents the version catalog strategy for the mobile-ai-harness project. All dependency versions must be declared in the version catalog to prevent drift, ensure reproducibility, and enable automated dependency updates.

## Version Catalog Location

### Android (Gradle Kotlin DSL)
- **File**: `gradle/libs.versions.toml`
- **Format**: TOML (Tom's Obvious Minimal Language)
- **All versions must be here**: No version hardcoding in build.gradle files or build scripts

### iOS (Swift Package Manager)
- **File**: `Package.swift` or SwiftPM manifest
- **Format**: SwiftPM format for dependencies
- **System dependencies**: Use Xcode/Swift built-in versions where possible

## Android Version Catalog Structure

### Gradle Plugin Versions
```toml
[plugins]
# Android Gradle Plugin - must match toolchain
android-studio = { version = "9.4.0.02", apply = false }

# KSP for Room 3 compilation
androidx.room = { version = "2.6.1", enableNative = true }
```

### Language Versions
```toml
[versions]
# Kotlin - must match MIN_JDK in harness.env
kotlin = "2.4.10"

# Java - for multi-module projects
java = "21"
```

### Framework and Library Versions
```toml
[versions]
# Jetpack Compose BOM - controls Compose versions
compose-bom = "2026.09.00"

# Room - KSP-only, Room 3.x
room = "3.0.0"

# Coroutines and Flow
kotlin-coroutines = "1.8.0"
kotlinx-coroutines-test = "2.6.0"

# Testing
junit = "4.2.0"
turbine = "1.3.0"
truth = "1.1.3"

# Material Components (if using)
material-components = "1.11.0"

# Lifecycle and Activity
lifecycle-runtime = "2.8.0"
lifecycle-runtime-ktx = "2.8.0"

# Material 3
material3 = "1.2.0"
```

### Plugin Declarations
```toml
[plugins]
# Room KSP plugin
androidx.room.ksp = { version = "3.0.0", artifacts = ["room-runtime", "room-compiler"] }

# Compose BOM - applies Complemented BOM
androidx.compose.bom = "2026.09.00"

# Koin (if used, switch to Hilt through ADR)
# koin = { group = "org.koin", version = "3.5.0" }
```

### Verification Commands
```bash
# Check Gradle wrapper version
./gradlew --version | head -5

# Check Kotlin version used by project
./gradwl -q kotlinStdlib

# Verify catalog consistency
./gradlew dependencies --configuration compileClasspath 2>&1 | grep -E "kotlin|room|compose"

# List all versions in catalog
cat gradle/libs.versions.toml
```

### Adding a New Dependency
1. **Check if version is already in catalog** - search `libs.versions.toml`
2. **Add version to `[versions]` section** with the latest stable release
3. **Add plugin declaration** if it's a build plugin (Room KSP, Compose BOM, etc.)
4. **Add library declaration** if it's a regular dependency
5. **Run `make validate-harness`** to ensure catalog consistency
6. **Update documentation** if version baseline changes

### Example: Adding Room 3.1.0
```toml
# In [versions] section
room = "3.1.0"

# In [plugins] section (if not already present)
androidx.room.ksp = { version = "3.1.0", artifacts = ["room-runtime", "room-compiler"] }
```

Then sync Gradle and verify:
```bash
./gradlew :app:dependencies --configuration compileKotlin
```

## iOS Version Management

### Swift Packages
Swift Packages are versioned by the package maintainer. The template does not use a local version catalog for iOS dependencies, but:

1. **Pin package versions** in `Package.resolved` (generated by Xcode)
2. **Xcode version**: Xcode 27 with Swift 6.4 (baseline)
3. **Swift language mode**: 6.4 (baseline); strict concurrency enforced
4. **Package dependencies**: Justify every dependency; no implicit dependencies

### Xcode Project Versions
- **Swift version**: Set in Xcode project settings (Swift 6 mode)
- **Deployment target**: Per `docs/stack.md` (default: iOS 26.0)
- **SDK version**: Xcode 27 provides iOS 27 SDK; Xcode 26.6 provides iOS 26 SDK

### Justifying Dependencies
Every Swift Package dependency must:
1. Have a stated reason in the PR
2. Be maintained and actively published
3. Not duplicate existing template functionality
4. Be documented in the PR description

## Version Drift Prevention

### Red Flags (investigate immediately)
- Building on a machine with different toolchain versions than documented
- `Package.resolved` out of sync with `Package.swift`
- Gradle cache having different versions than `libs.versions.toml`
- `make validate-harness` showing version-related errors
- Team members running different Kotlin/Swift versions

### Prevention Strategies
1. **All versions in catalog**: No version knowledge outside `libs.versions.toml` / `Package.swift`
2. **CI validation**: `make validate-harness` runs on every PR; fails on version drift
3. **Onboard new team members**: `sh init.sh` validates their environment against catalog
4. **Quarterly review**: Review `docs/stack.md` and update baseline if needed
5. ** Dependabot automation**: Configure `.github/dependabot.yml` for automatic updates (review required)

### When to Update the Baseline
1. **New stable release of critical dependency** (e.g., Kotlin 2.5.0 final, Compose 1.13 stable)
2. **Xcode point release** with important bug fixes or SDK updates
3. **AGP major version change** (currently AGP 9.x baseline)
4. **JDK major version change** (currently 17 via MIN_JDK)
5. **Another agent or human reports version-related issue**

### Update Process
1. **Write ADR** in `docs/decisions/` documenting the change and rationale
2. **Update `docs/stack.md`** with new baseline versions
3. **Update `gradle/libs.versions.toml`** (Android) or `Package.swift` (iOS)
4. **Run `make validate-harness`** to verify consistency
5. **Run sensors on existing features** to ensure no regression
6. **Update version baseline date** in `docs/stack.md`
7. **Record the decision** in `progress/log.md`

## Version Catalog Checklist

Before committing version changes, verify:
- [ ] All project dependencies are in the catalog
- [ ] No versions hardcoded in build files or source code
- [ ] Catalog versions match the baseline in `docs/stack.md`
- [ ] Plugin artifacts are correctly specified (Room KSP, Compose BOM)
- [ ] Test dependencies are separate from main dependencies
- [ ] Version ranges are not used (use exact versions only)
- [ ] `make validate-harness` passes
- [ ] Team members can build after changes (`sh init.sh` validates)
